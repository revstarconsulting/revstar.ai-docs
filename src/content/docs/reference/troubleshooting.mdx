---
title: Troubleshooting
description: Fixes for the v1 issues developers actually hit.
---

**Not sure what's wrong?** Open the app, go to **Settings → Diagnostics**, click
**Run diagnostics**, then **Copy report** and send it to the RevStar.ai maintainer.
In a terminal: `kiroctl diagnose --out report.txt`. See [Telemetry → Diagnostics report](/capabilities/telemetry/#diagnostics-report).

| Symptom | Fix |
| --- | --- |
| Settings → Mission Control shows **Rejected events** or **Heartbeat — REJECTED** (*Needs you*) | Mission Control refused those events and they were dropped. Run `kiroctl update`. If it continues, click **Download errors** next to Check now and send the saved file (in Downloads) to the maintainer. A rejection from before your last update shows as a *Note* and needs nothing. |
| `mission-state.js --clear` says **fan-out gate: REFUSED** | The mission's changes reach pages, endpoints or jobs that weren't tested since their code last changed (or weren't validly waived). The message lists them with the exact `qa-scoped-record.js` commands to run. Test them (or waive one with a tested stand-in of the same kind), `end` the run, then clear again. |
| Scoped QA lists **hundreds of targets** for a small change, or a mission spends hours in QA | QA is measuring against the wrong branch, usually a stale `staging` when the team works on `dev`. Check the `base <repo>: …` line QA prints. Set the project's Target branch (`kiroctl project set-env --dir <p> --branch dev`, or the app's QA environment card) and start the next mission with `--base-branch dev`. From **0.8.4** the branch is fixed at mission start and the diff matches a pull request's. On an older version, update first; a running mission keeps the base it started with, so close it with `--failed` and start a new one. |
| `qa-scoped-record.js` says the scoped record **stayed locked for 20s** | The lock folder `.qa-gate/scoped/<mission>.jsonl.lock` couldn't be cleared. A lock older than 5 seconds is normally cleared automatically, so this usually means a permissions problem on `.qa-gate/scoped/`. Fix the folder's permissions, or, if no QA is running, have a person remove the `.lock` folder (agents can't touch the scoped record). |
| You need a mission to clear without the fan-out check | Create `qa-fanout-gate.disabled` in `~/.kiro/gates/` (or the project's `.kiro/gates/`) **before** starting the mission. A flag created during a mission is ignored. |
| Settings → Mission Control shows **QA fan-out gate — failed open N times** | The check couldn't run (no git in a repo, or it took over 2 minutes), so those missions cleared without it. If it keeps happening, click **Download errors** and send the file to the maintainer. |
| A QA report is refused for **no verification method**, **PASS with note**, or **adversarial pass not cited** | Add `method: live` (or `inspection`/`code`, which can't PASS unless tagged `[cannot-exercise-on-staging]` with what staging lacks) to each verdict; turn any PASS that describes a problem into a FAIL; record the adversarial rounds with `qa-adversarial-receipt.js` and cite the receipt. |
| Mission Control shows work under the **wrong project** | Run **Settings → Diagnostics** and read **Project attribution**: it names the project each repo reports to and why. Fix with `kiroctl telemetry project --reset --dir <repo folder>`. If the right project isn't in *your projects*, ask the Mission Control team to add you to it first. |
| Developer is signed in but nothing shows in Mission Control, and diagnostics says **skill uses recorded: NONE** | The skill-use hook never fired on that machine. Check the **Live Kiro session test** rows: a `read denied … workspace-escape` line means Kiro refused to read the skill file, so the hook never saw it. Send the report to the maintainer. |
| Install stops with `FATAL: no co-located kiro/ and KIRO_REGISTRY_ROOT is not set` | You have an installer from before 2026-11-01. Download it again from the [Downloads page](https://revstarconsulting.net/dashboard/downloads) and re-run it. It now clones the registry itself. For a manual install, pass the location: `KIRO_REGISTRY_ROOT=../revstar.ai-registry`. |
| A bare `kiro-cli` says `profileArn is required` | Don't launch `kiro-cli` directly. Launch via `kiroctl open` (or the platform launcher), which handles client login first. |
| `kiroctl open`/`login` says `Already logged in, please logout with kiro-cli logout first` and won't sign in | The per-client sandbox is signed in as a different identity (a stale AWS Builder ID, or another client's IdC). kiroctl now detects this and logs the sandbox out before signing in, so `open`, `login`, and the GUI **Sign in with SSO** self-heal. On an older build, clear it manually: `kiroctl client reset-sandbox --slug <slug>` then `kiroctl login --slug <slug>` — and don't run a bare `kiro-cli logout`, which targets the wrong store. |
| Every prompt is refused with "You are not signed in to Mission Control" | Sign in once: `kiroctl gui` → **Sign in with Mission Control**. If Mission Control is down or the machine has no browser, `kiroctl sop bypass --hours 4 --reason mc-outage` (or `no-browser` / `other`; logged, max 72h). |
| `kiroctl doctor` / `telemetry status` says "queued — waiting on Mission Control" | Expected until Mission Control's per-developer ingest key is switched on. Events are kept and send automatically; nothing to do. |
| Telemetry not sending / says "kiroctl could not be found" | Re-run the installer (or `kiroctl update`) so `~/.kiro/kiroctl-install.json` records where the CLI lives, then `kiroctl telemetry repair`. |
| The app asks "Which Mission Control project is this repo for?" | The repo matches several of your projects. Pick one — it's asked once per repo and saved in `.kiro/telemetry-project.json` (commit it so your team doesn't get asked). |
| The app's **Mobile testing** card says **Mobile testing is off**, or the agent has no `mobilenext_*` tools | The client has no Mobile Next key, or the session started before it was saved. Add the key (app card or `kiroctl mobile key set --slug <client>`), run `kiroctl open`, and start a new session. See [Mobile app QA](/workflows/mobile-qa/#troubleshooting). |
| `kiroctl mobile key test` says the key was rejected, or the card shows **Needs you** | The key was revoked or mistyped. Replace it with `kiroctl mobile key set --slug <client>`. |
| Mobile QA stops with `staging check failed` or `cannot verify the build is a staging build` | The build's id is a production id, matches no app in any `qa-contract.json`, or can't prove staging. Fix the ids, upload the staging build, or tick **This build targets staging** in the app's form if it's true. Production builds are never tested. |
| Mobile QA stops with `balance is empty`, `below this run's cap`, or `cap reached` | Device minutes ran out or the run's cap was spent. Remaining screens are reported NOT COVERED. Top up or upgrade the Mobile Next plan (the Starter overage cap is a hard stop), or raise the contract's `minutesCap`. |
| Mobile devices still show as booked after a crashed or cancelled session | They bill until released, and Mobile Next auto-releases only after 120 minutes. Run `kiroctl mobile release --dir <project>` (or the app's **Release leftover devices** button). |
| Mobile QA reports an iOS or Android platform NOT COVERED, or change checks read NOT VERIFIED | There is no ready build for that platform (Android needs an APK, not an AAB; iOS an unsigned or ad-hoc IPA), or the build's commit is `unknown`. Upload a build and confirm its commit. |
| A gate doesn't fire | Confirm its `.enabled` flag file actually exists, then run `node kiro/gates/selftest.js` to isolate which gate is misbehaving. |
| ADO tools return `401` or no data | Your PAT isn't set (or lacks scope). Set it with `kiroctl client set-pat`, using a token with **Work Items Read & Write**. |
| On Windows (WSL), `kiroctl update` asks for a **GitHub username**, or fails with `could not read Username for 'https://github.com'` | Git inside WSL can't see your Windows GitHub sign-in. From **0.8.2** `kiroctl update` uses the Windows sign-in by itself (GitHub CLI or Git Credential Manager) when WSL's git has no GitHub login, and says so with `WSL: using your Windows GitHub sign-in`. On an older version, press **Ctrl+C** and update once by hand: `git -c credential.helper= -c "credential.https://github.com.helper=!'/mnt/c/Program Files/GitHub CLI/gh.exe' auth git-credential" -C <rvst-cli> pull` (`<rvst-cli>` is your `revstar.ai` clone), then run `kiroctl update` again, which now uses the new behaviour. If it still fails, check in Windows that `gh auth status` shows an account in the `revstarconsulting` org. |
| `kiroctl update` prints `UPDATE NOT APPLIED` / `layout: unknown` | It couldn't locate your pack content, so **nothing changed** (it exits non-zero — it won't masquerade as success). `update` auto-locates a sibling `rvst-registry` clone when the install manifest doesn't record one; if that fails, pass it explicitly: `kiroctl update --registry <path-to-rvst-registry>` (which also records the location so future updates self-resolve). Then **restart the session** so the refreshed steering/skills/MCP config loads. |
| Registry signature verification failed | The manifest must be signed with the key matching `kiroctl`'s embedded public key. A manifest signed with a different key will always fail verification. |
| Changes not taking effect | Restart the `kiro-cli` session. Steering, skills, and MCP servers all load at session start — an edit made mid-session isn't picked up until the next one. |
| Too many project launch icons on the desktop (or you want them elsewhere) | Those per-project `.desktop`/`.command`/`.lnk` icons are **optional convenience launchers** — nothing requires them on the desktop (everything works from `kiroctl gui` / `kiroctl open`). Relocate them: **Settings → Project launchers** (set a folder, Browse, Save; or Reset to Desktop), or from the terminal `kiroctl launchers --dir <path>` (`--show` / `--reset`). The `KIRO_DESKTOP` env var overrides both. Default is `~/Desktop`; the change applies to launchers created from then on (existing icons stay until you reopen those projects). |
| A model becomes unavailable mid-session | Known Kiro platform issue. Autonomous missions driven by `mission-acp-driver.js` **retry, then fall back automatically** `claude-opus-5.5 → claude-opus-4.8 → claude-opus-4.7` (the live session resets but the mission re-injects and continues from the task list + ledger). Sub-agents fall back `claude-sonnet-5.5 → claude-sonnet-5 → claude-sonnet-4.6` by re-delegation. In a plain interactive session (no driver), switch manually with `/model claude-opus-4.8`. |
| Signed in, heartbeats arrive, but Mission Control shows **zero skill usage** | On Kiro 2.37+ the read tool was renamed, which stopped skill-use recording in older packs. Update RevStar.ai (`kiroctl update`, 0.6.7+). Confirm with **Settings → Diagnostics → Live Kiro session test** — "skill use recorded: yes". |
| Diagnostics reports an **agent name conflict** / sessions run without hooks | A stray file in `~/.kiro/agents` declares its internal `name` as `dev`, `coder` or `scout`, so Kiro loads an ambiguous agent that can skip the telemetry and governance hooks. Delete or rename the stray file (keep only `dev.json` / `coder.json` / `scout.json`). |
| `kiro-cli` behaves oddly / features silently fail on an older install | Your `kiro-cli` may be out of date. Run `kiroctl doctor` — it now **WARNs** when `kiro-cli` is below the recommended version. Update via the installer at `cli.kiro.dev/install`, then restart the session. |
| QA render can't launch a browser on Linux (no display) | A headed browser needs a display server. On a display-less Linux host, install Xvfb (`sudo apt-get install -y xvfb`); the pack auto-wraps the Playwright MCP in `xvfb-run`. On **macOS** QA renders **headless** by default (see next row); Windows renders headed on its desktop. |
| QA browser steals focus / keeps jumping to the front on macOS | A headed Chromium on macOS activates on every navigation and grabs keyboard focus — there's no reliable macOS setting to stop it. The pack now renders QA **headless** on macOS (screenshots are the evidence; same render fidelity). Update via the installer and restart the session. |
| `/goal` pauses between turns and needs a manual "continue" | Expected in the plain interactive TUI: Kiro's stop hook can't block, so the agent goes dormant at each turn's end. For hands-off auto-continue, drive the mission with `node <pack>/bin/mission-acp-driver.js` (one persistent session that re-prompts itself until the mission clears). |
| Says it's complete but still shows "N tasks remaining" | An unchecked to-do reads as remaining work and re-fires the goal loop. The agent now marks each item the moment its work is verified and reconciles the list before claiming done; if you see stragglers, ask it to "reconcile the task list and clear anything finished." |
| Stuck spinning on a deployment that never comes up | QA needs the target deploy live. The agent now bounds the wait, tries to fix the deploy, and if it can't, **stops with a `human-blocked` blocker** naming the failure for you to fix — rather than spinning indefinitely. |
| A shell command hangs for many minutes on macOS with no timeout | Known `kiro-cli` limitation: on macOS its shell tool has no per-command timeout (Windows times out on its own). Recovery: tell the agent "the shell has been pending for N minutes," then press **Enter → Escape** to move it to the pending queue so it re-routes. Prefer backgrounding long-running commands (dev servers, installs). Reported upstream. |
| ADO PAT is set but the session still can't use it (or uses an old one) | The PAT is injected when you **`open`** the project. Set it *before* opening; if you change it, **relaunch** the session — a running session keeps the value it launched with. |
| An MCP server shows a failure on first startup | Often a cold-start flake (e.g. `npx` fetching the server on first run). Restart the session and it usually clears. If it persists, run `kiroctl doctor` and check `~/.kiro/settings/mcp.json`. |
