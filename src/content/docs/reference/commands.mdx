title: Command reference
description: The complete kiroctl command surface — one line each.
---

`kiroctl` is the only CLI surface. The commands below are the complete set —
there is no `link`, `unlink`, or `install @latest`.

| Command | What it does |
| --- | --- |
| `kiroctl client add \| list \| rm` | Register, list, or remove clients. |
| `kiroctl client set-pat --slug <s>` | Set that client's Azure DevOps PAT, read from stdin. |
| `kiroctl project new --dir --client [--scaffold]` | Create a new client-bound project at `--dir`. |
| `kiroctl open --dir [--run [--prompt "<line>"]]` | Launch a project's Kiro session, optionally running a command on start. The chat runs on Kiro's v2 engine (`--agent-engine v2`) when your kiro-cli supports it, so a mission keeps going between turns. `--run` launches `kiro-cli chat --agent-engine v2 --agent dev --model claude-opus-5.5 --effort medium --trust-all-tools`: the chat a [mission](/workflows/missions/) runs in. **0.11.0 (beta).** `--prompt` sends a first message, for example `/build-plan plan=plan.md`. When the client has a Mobile Next key, also passes it as `MOBILENEXT_API_KEY` and writes the project's `mobilenext` MCP entry. |
| `kiroctl profile --dir [--platform iterm2\|linux] [--install]` | Generate (and optionally install) a terminal launch profile. |
| `kiroctl doctor [--governance]` | Diagnose the local setup; `--governance` also checks capability governance rules. Adds mobile testing rows for projects with a mobile repo or a Mobile Next key. **0.11.0 (beta).** An `agent-engine` row warns when kiro-cli's engine is v3, where a mission chat does not continue itself. See [the chat keeps itself going](/workflows/missions/#the-chat-keeps-itself-going). A `mission-loops` row warns about any active mission whose chat or headless runner is dead, with the fix (`kiroctl open --run` in that folder). A `hook <name>` row for each of the four safe hooks says whether it is armed, off by choice or not armed. A `channel-branch` row warns when the CLI or registry clone isn't on its channel's branch, and gives the fix. A `skill frontmatter` row fails, naming each skill, when an installed skill won't load in Kiro (invalid YAML frontmatter, or a description over 1024 characters). **0.11.0 (beta).** A `workflows` row fails when kiro-cli Workflows are on, with the fix `kiro-cli settings chat.enableWorkflows false`. The installer and `kiroctl update` turn them off, because a `/goal` workflow skips the pack's hooks. A `global-hook` row fails when `~/.kiro/hooks/revstar-workbench.json` is missing or names a `global-hook.js` that is missing (fix: `kiroctl update`), and warns when the file holds more than the three gates. The old `goal-loop` row is gone. See [Gates → The global hook](/capabilities/gates/#the-global-hook). |
| `kiroctl diagnose [--no-live] [--json] [--out <file>]` | Full self-diagnostic report to send to the maintainer: install, skills, connections, telemetry, and a live Kiro session test (`--no-live` skips it). Same as the app's **Settings → Diagnostics**. |
| `kiroctl onboard --kind --name --source` | Register a custom skill, agent, or hook (`--kind skill\|agent\|hook`). |
| `kiroctl sync [--target --ref]` | Pull registry updates into the project, edit-preserving. |
| `kiroctl ado telemetry [--json]` | Read-only Azure DevOps sprint/work-item/roadmap snapshot. |
| `kiroctl kb refresh [--dry-run]` | Regenerate the project's knowledge base. |
| `kiroctl gui [--qa-url [--port <n>]]` | Launch the GUI. `--qa-url` instead prints a one-time URL for a QA browser from the **running** app, so nobody reads the app's token log. Refused while all agents are stopped or the caller's mission is paused. |
| `kiroctl missions [list \| pause <id> \| resume <id> \| end <id> \| stop-all \| resume-all] [--yes] [--json]` | The app's Missions drawer in a terminal; works when the app isn't running. From 0.10.0 `list` also shows a lane mission's lane, its state and the PRs registered. From 0.11.0 (beta) it shows a headless runner as running, stopped (with the reason) or dead. Pause or resume one mission, end it, or stop or resume every Kiro agent on the machine. Pause, end and stop-all ask for confirmation (`--yes` skips it). **0.11.0 (beta).** `end` runs `mission-state.js --clear --failed "ended from the app"` as the person (it sets `KIROCTL_PERSON_ACTION=1`). Agents are refused all of it except `list`. See [Stopping a mission](/workflows/missions/#stopping-a-mission). |
| `kiroctl registry fetch \| verify` | Fetch or verify the signature of the capability registry. |
| `kiroctl update [--check] [--registry <path>] [--channel <beta\|stable>] [--yes]` | Update kiroctl itself; `--check` reports without applying. Puts both repos on the channel's branch (`stable`, or `v1` for beta) and fast-forwards them; it never stashes or resets, and stops on uncommitted changes or a diverged branch. `--channel` switches and records the channel. A stable install found on `v1` is asked "Move back to stable? This drops beta features." (no terminal or "no" stays on beta); `--yes` answers yes. See [Release channels](/start/install/#release-channels--stable-vs-beta). |
| `kiroctl version` | Print the installed `kiroctl` version. |
| `kiroctl client set-ado --slug <s> [--ado-org --ado-project --ado-pm]` | Set the client's Azure DevOps org URL, default project, and PM (injected on open). |
| `kiroctl project set-env --dir [--base-url --env --branch --backend-query]` | Capture the project's staging/dev QA target + access; scaffolds `qa-contract.json`. `--branch` is the Target branch: the branch work merges into, which scoped QA diffs against. It never writes the `access` declaration: [declare access](/workflows/missions/#access-you-must-declare-it) yourself before the first mission. |
| `kiroctl mobile key set \| test \| remove --slug <client>` | Mobile app QA: store the client's Mobile Next API key (`set` reads it from stdin and tests it first), re-check it with its plan and minutes left, or remove it. See [Mobile app QA](/workflows/mobile-qa/). |
| `kiroctl mobile status [--dir]` | Mobile testing readiness for a project: key, minutes left, each repo's contract, builds, accounts, devices still booked. |
| `kiroctl mobile release [--dir]` | Release Mobile Next devices a crashed session left booked (they bill until released). |
| `kiroctl qa secret get \| set --ref secret:<name>` | Read or store a test-account password in the OS secret store. `get` prints only the value; `set` reads stdin. |
| `kiroctl qa account add \| list \| rm --dir <repo> [--role --username]` | Manage a repo's test accounts: `add` reads the password from stdin, stores it in the secret store, and writes a `secret:` reference to `qa-test-cases/test-credentials.md`. |
| `node <pack>/bin/mobile-qa.js <subcommand>` | The helper the `qa` skill drives during a mobile test, not a `kiroctl` command: `status`, `preflight`, `upload`, `resolve-build`, `pick`, `teardown`, `screenshot`, `prune`, `account-add`, `account-cleanup`. Reads `MOBILENEXT_API_KEY`; `--json` for machine output. |
| `node <pack>/bin/grill-receipt.js import --from <file> --root <project> --ado-id <N> --ado-title <title> --confirmed-by <name> [--narrow a,b] [--defer name="reason"] [--replace]` | **0.11.0 (beta).** Import a plan someone else grilled: copies it to `<project>/.kiro/plans/<id>-<slug>.md` and writes an `imported` grill receipt. Every access probe in the project's `qa-contract.json` must pass; `--narrow` keeps only the probes the plan needs, and `--defer` defers one to kickoff with a reason. Not a `kiroctl` command; the app's **Import a pre-grilled plan** runs it. See [Import a pre-grilled plan](/workflows/missions/#import-a-pre-grilled-plan). |
| `node <pack>/bin/grill-receipt.js check <plan>` | **0.11.0 (beta).** Prints the plan's receipt kind: `grilled`, `imported` or `legacy`. |
| `node <pack>/bin/mission-acp-driver.js` | **0.11.0 (beta).** Runs a mission with no terminal, headless. It stops for the same reasons as the mission chat, writes a heartbeat, refuses an ambiguous folder, and allows one live runner per mission. Not a `kiroctl` command. |
| `node <pack>/bin/mission-broker.js status [--live] \| claim \| release \| add-pr <N> [--repo <dir>]` | **0.10.0 (beta).** A lane mission's broker lease, by hand or for recovery: show it (`--live` also asks the broker), claim or re-check it now, give it back now, or register a PR. Not a `kiroctl` command; merges register themselves. See [Missions in a lane](/workflows/missions/#missions-in-a-lane). |
| `node <pack>/bin/mission-state.js --verify-status [--json]` | **0.11.0 (beta).** The completion verifier's verdict for this mission: `pending`, `pass`, `stale` (a pass for an older ledger or older code), `fail` (with the rejected criteria and why), `error` or `none`. Exits 0 only for `pass`. `--set audit` starts the verifier; `--clear` needs `pass`. See [The completion verifier](/workflows/missions/#the-completion-verifier). |
| `node <pack>/bin/mission-state.js --verify-override <id> --reason "<why>"` | **0.11.0 (beta).** A person's decision on a criterion the verifier rejected three times: count it as accepted for the current ledger. Refused unless stdin is a terminal and the session is on none of `dev`, `coder`, `scout`. The reason is at least 15 characters; who, when and why are recorded and appear in the honest-exit record. |
| `node <pack>/bin/mission-state.js --clear [--repos <paths> \| --no-repos]` | **0.11.0 (beta).** Ends a finished mission. Refused unless the state is `audit` and the acceptance ledger is complete, whether or not any gate is armed. `access-descoped:*` and `skipped:*` criteria don't block but make the exit PARTIAL, as does an advisory mission with no ledger. See [Clearing a mission](/workflows/missions/#clearing-a-mission). |
| `node <pack>/bin/mission-state.js --clear --failed "<reason>"` | **0.11.0 (beta).** The person's way out of an unfinished mission: records the exit as FAILED. The reason must be at least 15 characters. Refused from a `dev`, `coder` or `scout` session unless `KIROCTL_PERSON_ACTION=1` (the app's End and `kiroctl missions end` set it). |
| `node <pack>/bin/grill-receipt.js write <plan>` | **0.11.0 (beta).** Writes the plan's grill receipt after the `## Required Access` check resolves. The receipt now records `rules: 2`, which a mission started from it copies into its gate sidecar. See [Tying criteria to the plan](/workflows/missions/#tying-criteria-to-the-plan-rules-v2). |
| `node <pack>/bin/mission-state.js --accept-add --id <id> --req "<text>" --plan-ref "<exact plan sentence>" [--phase P] [--target N]` | **0.11.0 (beta).** Adds an acceptance criterion. `--plan-ref` is required when the plan was grilled under rules v2 and must be a sentence in the plan (whitespace, `**` and backticks ignored); under rules 1 it is optional and checked when given. |
| `node <pack>/bin/mission-state.js --accept-set --id <id> --verdict MET --evidence "<proof>" --cite <path:line>[,<path:line>...]` | **0.11.0 (beta).** Records a verdict. `MET` needs `--cite` when the criterion has a `planRef` or the plan was grilled under rules v2: each file and line must exist, and every number and quoted value in the plan sentence must be within 15 lines of a cite (numbers as numbers, so `10%` is not `10x` or `0.10`). A miss is refused. |
| `node <pack>/bin/qa-adversarial-receipt.js record --round <n> --tried "<what>" --result "<what happened>" --findings <k> [--fixed "<commit or note>"]` | **0.11.0 (beta).** Records one adversarial round of a QA run. `--tried` needs 20 characters and `--result` 10. `--fixed` is for a round with findings. A round recorded without `tried` counts toward no empty round. `show` prints each round. |
| `node <pack>/bin/mission-state.js --accept-rm --id <id> --reason "<why>"` | **0.11.0 (beta).** Takes a criterion out of the ledger on purpose. The reason must be at least 15 characters. The criterion is kept in `removed[]`, and `--accept-show` and the honest-exit record list it with its reason. |
| `kiroctl mission-report [--dir] [--transcript]` | Write a local, secret-scrubbed diagnostics bundle for auditing a mission run (no upload). |
| `kiroctl telemetry status \| repair \| flush \| config \| project \| probe-allowlist` | Adoption telemetry: identity + queue + connection health, run the self-repair now, manual flush, endpoint config, Mission Control project pin, and (maintainers) send two real events to check Mission Control accepts the `project_status` and `hours_source` fields. |
| `kiroctl sop status \| signout` | Mission Control sign-in (telemetry + SOP standards): show the connection state, or sign out. Sign **in** only in the app (`kiroctl gui` → "Sign in with Mission Control"). |
| `kiroctl sop bypass --hours <1-72> [--reason mc-outage\|no-browser\|other] \| --clear` | Time-limited, logged bypass of the sign-in gate (reported to Mission Control). |
| `kiroctl sop nudge` | What the installer runs at the end: signed out → open the app on its sign-in banner, or print the instruction (no display / `KIRO_NO_GUI=1`). |
| `kiroctl sop token [--force]` | Tooling: print a fresh id-token from the stored sign-in (`--force` re-mints). |

## What doesn't exist

- **No `link` / `unlink`.** Project binding happens at `kiroctl project new` /
  `kiroctl open` time; staying current is `kiroctl sync`.
- **No `install @latest`.** Updating the CLI itself is `kiroctl update`.
