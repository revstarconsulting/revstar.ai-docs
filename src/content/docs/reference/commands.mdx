`kiroctl` is the only CLI surface. The commands below are the complete set —
there is no `link`, `unlink`, or `install @latest`.

| Command | What it does |
| --- | --- |
| `kiroctl client add \| list \| rm` | Register, list, or remove clients. |
| `kiroctl client set-pat --slug <s>` | Set that client's Azure DevOps PAT, read from stdin. |
| `kiroctl project new --dir --client [--scaffold]` | Create a new client-bound project at `--dir`. |
| `kiroctl open --dir [--run [--prompt "<line>"]]` | Launch a project's Kiro session, optionally running a command on start. The chat runs on Kiro's v2 engine (`--agent-engine v2`) when your kiro-cli supports it, so a mission keeps going between turns. `--run` launches `kiro-cli chat --agent-engine v2 --agent dev --model claude-opus-5.5 --effort medium --trust-all-tools`: the chat a [mission](/workflows/missions/) runs in. **0.11.0.** `--prompt` sends a first message, for example `/build-plan plan=plan.md`. When the client has a Mobile Next key, also passes it as `MOBILENEXT_API_KEY` and writes the project's `mobilenext` MCP entry. **0.11.0.** In a git worktree of a bound project that has no `.kiro/client` of its own, `open` (and `kiroctl env`) use the main checkout's client binding. |
| `kiroctl profile --dir [--platform iterm2\|linux] [--install]` | Generate (and optionally install) a terminal launch profile. |
| `kiroctl doctor [--governance]` | Diagnose the local setup; `--governance` also checks capability governance rules. Adds mobile testing rows for projects with a mobile repo or a Mobile Next key. **0.11.0.** An `agent-engine` row warns when kiro-cli's engine is v3, where a mission chat does not continue itself. See [the chat keeps itself going](/workflows/missions/#the-chat-keeps-itself-going). A `mission-loops` row warns about any active mission whose chat or headless runner is dead, with the fix (`kiroctl open --run` in that folder). A `hook <name>` row for each of the five default hooks (the four safe hooks and `mission-state-protect`) says whether it is armed, off by choice or not armed. A `channel-branch` row warns when the CLI or registry clone isn't on its channel's branch, and gives the fix. A `skill frontmatter` row fails, naming each skill, when an installed skill won't load in Kiro (invalid YAML frontmatter, or a description over 1024 characters). **0.11.0.** A `workflows` row fails when kiro-cli Workflows are on, with the fix `kiro-cli settings chat.enableWorkflows false`. The installer and `kiroctl update` turn them off, because a `/goal` workflow skips the pack's hooks. A `global-hook` row fails when `~/.kiro/hooks/revstar-workbench.json` is missing or names a `global-hook.js` that is missing (fix: `kiroctl update`), and warns when the file holds more than the three gates. The old `goal-loop` row is gone. See [Gates → The global hook](/capabilities/gates/#the-global-hook). **0.11.0.** A `hook-drift` row reads `~/.kiro/logs/hook-drift.log` (and its rotated `.1` file). It passes when the last 7 days hold no event a gate could not read, and warns with the count per kind (`unparseable`, `utf16`, `no-tool-name`, `no-command`, `no-path`, `unknown-tool`), the newest example and the log path. The `kiro-cli` row now also compares the installed version with the range the gates were probed live on (`2.0.0` to `2.37.1`, from the pack's `tested-kiro.json`) and warns when it is older or newer. A `gates` row lists which of the six blocking gates are armed, off by choice (`.disabled`) or not armed, and the three always-on ones (`mission-pause`, `broker-merge-gate`, `tool-watchdog`). A `tool-watchdog` row says `on (limit 30 min)`, warns when its off-switch file exists, and reports calls ended as stuck in the last 24 hours and sub-agents that went quiet. See [Troubleshooting](/reference/troubleshooting/). |
| `kiroctl diagnose [--no-live] [--json] [--out <file>]` | Full self-diagnostic report to send to the maintainer: install, skills, connections, telemetry, and a live Kiro session test (`--no-live` skips it). **0.11.0.** The live test also runs the installed `dev` agent's write and shell hooks on synthesized events in a throwaway folder and checks each answers (exit 0 or 2, with the time), that an armed gate refuses its hostile test event, and lists tool names in the hook-drift log that the gates do not classify. The Doctor section carries the new `hook-drift`, `gates` and `tool-watchdog` rows. Same as the app's **Settings → Diagnostics**. |
| `kiroctl onboard --kind --name --source` | Register a custom skill, agent, or hook (`--kind skill\|agent\|hook`). |
| `kiroctl sync [--target --ref]` | Pull registry updates into the project, edit-preserving. |
| `kiroctl ado telemetry [--json]` | Read-only Azure DevOps sprint/work-item/roadmap snapshot. |
| `kiroctl kb refresh [--dry-run]` | Regenerate the project's knowledge base. |
| `kiroctl gui [--qa-url [--port <n>]]` | Launch the GUI. `--qa-url` instead prints a one-time URL for a QA browser from the **running** app, so nobody reads the app's token log. Refused while all agents are stopped or the caller's mission is paused. |
| `kiroctl missions [list \| pause <id> \| resume <id> \| end <id> \| approve <id> --budget <n> \| decline <id> \| stop-all \| resume-all] [--yes] [--json]` | The app's Missions drawer in a terminal; works when the app isn't running. From 0.10.0 `list` also shows a lane mission's lane, its state and the PRs registered. From 0.11.0 it shows a headless runner as running, stopped (with the reason) or dead. Pause or resume one mission, end it, or stop or resume every Kiro agent on the machine. Pause, end and stop-all ask for confirmation (`--yes` skips it). **0.11.0.** `end` runs `mission-state.js --clear --failed "ended from the app"` as the person (it sets `KIROCTL_PERSON_ACTION=1`). **0.12.0.** `approve` records your approval of a QA mission's estimate with its device-minute budget, and `decline` ends that mission PARTIAL with its test registry kept; re-open the chat with `kiroctl open --dir <project> --run` after `approve`. Agents are refused all of it except `list`. See [Stopping a mission](/workflows/missions/#stopping-a-mission). |
| `kiroctl registry fetch \| verify` | Fetch or verify the signature of the capability registry. |
| `kiroctl update [--check] [--registry <path>] [--channel <beta\|stable>] [--yes]` | Update kiroctl itself; `--check` reports without applying. Puts both repos on the channel's branch (`stable`, or `v1` for beta) and fast-forwards them; it never stashes or resets, and stops on uncommitted changes or a diverged branch. `--channel` switches and records the channel. A stable install found on `v1` is asked "Move back to stable? This drops beta features." (no terminal or "no" stays on beta); `--yes` answers yes. See [Release channels](/start/install/#release-channels--stable-vs-beta). |
| `kiroctl version` | Print the installed `kiroctl` version. |
| `kiroctl client set-ado --slug <s> [--ado-org --ado-project --ado-pm]` | Set the client's Azure DevOps org URL, default project, and PM (injected on open). Also `--done-state`, `--done-assignee` and, **0.11.0.** `--start-state "<state>" [--state-path "A,B,C"]` (injected as `ADO_START_STATE` and `ADO_STATE_PATH`; `""` clears). See [Set up ADO for a client](/workflows/azure-devops/#set-up-ado-for-a-client-org-project-pat). |
| `kiroctl project set-env --dir [--base-url --env --branch --backend-query]` | Capture the project's staging/dev QA target + access; scaffolds `qa-contract.json`. `--branch` is the Target branch: the branch work merges into, which scoped QA diffs against. It never writes the `access` declaration: [declare access](/workflows/missions/#access-you-must-declare-it) yourself before the first mission. |
| `kiroctl mobile key set \| test \| remove --slug <client>` | Mobile app QA: store the client's Mobile Next API key (`set` reads it from stdin and tests it first), re-check it with its plan and minutes left, or remove it. See [Mobile app QA](/workflows/mobile-qa/). |
| `kiroctl mobile status [--dir]` | Mobile testing readiness for a project: key, minutes left, each repo's contract, builds, accounts, devices still booked. |
| `kiroctl mobile release [--dir]` | Release Mobile Next devices a crashed session left booked (they bill until released). |
| `kiroctl qa secret get \| set --ref secret:<name>` | Read or store a test-account password in the OS secret store. `get` prints only the value; `set` reads stdin. |
| `kiroctl qa account add \| list \| rm --dir <repo> [--role --username]` | Manage a repo's test accounts: `add` reads the password from stdin, stores it in the secret store, and writes a `secret:` reference to `qa-test-cases/test-credentials.md`. |
| `node <pack>/bin/mobile-qa.js <subcommand>` | The helper the `qa` skill drives during a mobile test, not a `kiroctl` command: `status`, `preflight`, `upload`, `resolve-build`, `pick`, `teardown`, `run`, `screenshot`, `prune`, `account-add`, `account-cleanup`. Reads `MOBILENEXT_API_KEY`; `--json` for machine output. |
| `node <pack>/bin/mobile-qa.js run --platform android\|ios --devices <n> [--entry <kind>] [--min-os <v>] [--bundle <id>] -- <command...>` | **0.12.0.** A scripted (not agent-driven) device run, such as `npx mobilewright test`. Books the devices, records them in the billing ledger, runs the command with `MOBILENEXT_DEVICES` set, and always releases them. Refuses with exit 3 and `BUDGET-EXHAUSTED` when the next booking would pass the mission's device-minute budget, or `ESTIMATE-NOT-APPROVED` while an estimate-first mission waits for your approval. Otherwise the exit code is the command's. See [Scripted device runs](/workflows/mobile-qa/#scripted-device-runs). |
| `kiroctl ci-detect --dir <project> [--json]` | **0.12.0.** Lists the CI/CD systems the project's repos already use: Azure Pipelines, GitHub Actions, CodeBuild buildspec, GitLab, Bitbucket and Jenkins. A regression mission uses it to wire into the existing system and never adds a new one. |
| `kiroctl ci-secret probe --dir <project> --system github\|azure\|aws --target <t> [--json]` | **0.12.0.** Says whether this machine can write CI secrets there. The target is a GitHub `owner/repo`, an Azure variable group id or an AWS secret-name prefix. Prints `possible` or `not possible` with the reason. |
| `kiroctl ci-secret set --dir <project> --system github\|azure\|aws --target <t> --name <NAME> --from qa.<ref>\|mobilenext.<slug>\|qa-base-url [--json]` | **0.12.0.** Copies a local secret into the CI secret store without showing it. The value goes straight from the local secret store to the CI store, and the output shows names only. Exit 2 means the request was refused, 1 means it could not write. |
| `kiroctl project rename --dir <project> --name <new> [--update-refs]` | **0.12.0.** Renames the project folder. Refused while a mission is running or paused there. It rewrites the references kiroctl owns, and lists any other file that still names the old path. `--update-refs` rewrites those too, after backing each up as `<file>.bak-<timestamp>`. The app's **Rename** and **Update these** do the same. A mission also blocks the rename, see [Troubleshooting](/reference/troubleshooting/). |
| `node <pack>/bin/grill-receipt.js import --from <file> --root <project> --ado-id <N> --ado-title <title> --confirmed-by <name> [--narrow a,b] [--defer name="reason"] [--replace]` | **0.11.0.** Import a plan someone else grilled: copies it to `<project>/.kiro/plans/<id>-<slug>.md` and writes an `imported` grill receipt. Every access probe in the project's `qa-contract.json` must pass; `--narrow` keeps only the probes the plan needs, and `--defer` defers one to kickoff with a reason. Not a `kiroctl` command; the app's **Import a pre-grilled plan** runs it. See [Import a pre-grilled plan](/workflows/missions/#import-a-pre-grilled-plan). |
| `node <pack>/bin/grill-receipt.js check <plan>` | **0.11.0.** Prints the plan's receipt kind: `grilled`, `imported` or `legacy`. |
| `node <pack>/bin/mission-acp-driver.js` | **0.11.0.** Runs a mission with no terminal, headless. It stops for the same reasons as the mission chat, writes a heartbeat, refuses an ambiguous folder, and allows one live runner per mission. Not a `kiroctl` command. |
| `node <pack>/bin/mission-broker.js status [--live] \| claim \| release \| add-pr <N> [--repo <dir>]` | **0.10.0.** A lane mission's broker lease, by hand or for recovery: show it (`--live` also asks the broker), claim or re-check it now, give it back now, or register a PR. Not a `kiroctl` command; merges register themselves. See [Missions in a lane](/workflows/missions/#missions-in-a-lane). |
| `node <pack>/bin/mission-state.js --verify-status [--json]` | **0.11.0.** The completion verifier's verdict for this mission: `pending`, `pass`, `stale` (a pass for an older ledger or older code), `fail` (with the rejected criteria and why), `error` or `none`. Exits 0 only for `pass`. `--set audit` starts the verifier; `--clear` needs `pass`. See [The completion verifier](/workflows/missions/#the-completion-verifier). |
| `node <pack>/bin/mission-state.js --verify-override <id> --reason "<why>"` | **0.11.0.** A person's decision on a criterion the verifier rejected three times: count it as accepted for the current ledger. Refused unless stdin is a terminal and the session is on none of `dev`, `coder`, `scout`. The reason is at least 15 characters; who, when and why are recorded and appear in the honest-exit record. |
| `node <pack>/bin/mission-state.js --set human-blocked-confirmed --blocker <id>` | **0.11.0.** The honest BLOCKED exit. `<id>` must be a dependency the governing plan declared (`## Dependencies`, or `## Required Access` with a covering probe) whose check **fails right now**; the script runs it. An undeclared id and a check that passes are refused. The id, the check's output tail and the time are recorded and shown by `show`, `--json`, `--verify-status` and the honest-exit record (`blockedBy`). A mission with no governing plan uses `--blocker-reason "<why, at least 15 characters>"` instead, recorded as unverified. `--yield human-blocked-confirmed` needs the same. See [Completion honesty](/workflows/missions/#completion-honesty-blocked-is-not-complete). |
| `node <pack>/bin/mission-state.js --init ... --ack-skipped "<checks>"` (or `--force`) | **0.11.0.** Waives preflight checks. A person's decision: refused for a `--preapproved` mission, when stdin is not a terminal, and from `dev`, `coder` or `scout`. Each waived check becomes the criterion `skipped:<check>` (`GAP`, with who acknowledged it), so the mission can only end PARTIAL. See [Missions](/workflows/missions/). |
| `node <pack>/bin/mission-state.js --clear [--repos <paths> \| --no-repos]` | **0.11.0.** Ends a finished mission. Refused unless the state is `audit` and the acceptance ledger is complete, whether or not any gate is armed. `access-descoped:*` and `skipped:*` criteria (and, from 0.12.0, `needs-decision:*` and `budget-exhausted:*` ones) don't block but make the exit PARTIAL, as does an advisory mission with no ledger. Under rules v2 every plan phase that has criteria must also be closed (`--phase-end`). See [Clearing a mission](/workflows/missions/#clearing-a-mission). |
| `node <pack>/bin/mission-state.js --clear --failed "<reason>"` | **0.11.0.** The person's way out of an unfinished mission: records the exit as FAILED. The reason must be at least 15 characters. Refused from a `dev`, `coder` or `scout` session unless `KIROCTL_PERSON_ACTION=1` (the app's End and `kiroctl missions end` set it). Mission Control gets `mission_failed`: the reason is `abandoned`, `error`, `blocked` or `timeout` when the text is one of those words, otherwise `abandoned` with the text as detail (200 characters at most). |
| `node <pack>/bin/mission-state.js --clear --ack-skipped qa` | **0.11.0.** A person's way to clear without the QA fan-out record. The mission ends PARTIAL with the criterion `skipped:qa`, naming who acknowledged it. Refused without a terminal, from a pack agent and in a `--preapproved` mission. Only `qa` is accepted. See [Clearing a mission](/workflows/missions/#clearing-a-mission). |
| `node <pack>/bin/grill-receipt.js write <plan>` | **0.11.0.** Writes the plan's grill receipt after the `## Required Access` check resolves. The receipt now records `rules: 2`, which a mission started from it copies into its gate sidecar. See [Tying criteria to the plan](/workflows/missions/#tying-criteria-to-the-plan-rules-v2). |
| `node <pack>/bin/mission-state.js --accept-add --id <id> --req "<text>" --plan-ref "<exact plan sentence>" [--phase N] [--target N]` | **0.11.0.** Adds an acceptance criterion. `--plan-ref` is required when the plan was grilled under rules v2 and must be a sentence in the plan (whitespace, `**` and backticks ignored); under rules 1 it is optional and checked when given. Under rules v2, when the plan has `### Phase N` headings, `--phase N` is required and must name one of them, and an id `F<N>.<m>` must carry its own N (`access-descoped:*`, `skipped:*` and `sop-standards` are phase-less). See [Phases](/workflows/missions/#phases-rules-v2). |
| `node <pack>/bin/mission-state.js --phase-end <N> [--repos <paths> \| --no-repos]` | **0.11.0.** Closes plan phase N (rules v2, a plan with phase headings). Refused unless every criterion of the phase is MET, no lower phase with criteria is open and, when the phase's changes reach a page, endpoint or job, a scoped QA run ended with nothing failed after the last code change. Closing a closed phase does nothing. Writes `.kiro-mission.<sid>.phases.json`, which only this command writes. Phases are strictly ordered: `--accept-set ... --verdict MET` on phase N is refused while a lower phase is open, and `--clear` needs every phase closed. See [Phases](/workflows/missions/#phases-rules-v2). |
| `node <pack>/bin/mission-state.js --accept-set --id <id> --verdict MET --evidence "<proof>" --cite <path:line>[,<path:line>...]` | **0.11.0.** Records a verdict. `MET` needs `--cite` when the criterion has a `planRef` or the plan was grilled under rules v2: each file and line must exist, and every number and quoted value in the plan sentence must be within 15 lines of a cite (numbers as numbers, so `10%` is not `10x` or `0.10`). A miss is refused. |
| `node <pack>/bin/qa-adversarial-receipt.js record --round <n> --tried "<what>" --result "<what happened>" --findings <k> [--fixed "<commit or note>"]` | **0.11.0.** Records one adversarial round of a QA run. `--tried` needs 20 characters and `--result` 10. `--fixed` is for a round with findings. A round recorded without `tried` counts toward no empty round. `show` prints each round. |
| `node <pack>/bin/mission-state.js --accept-rm --id <id> --reason "<why>"` | **0.11.0.** Takes a criterion out of the ledger on purpose. The reason must be at least 15 characters. The criterion is kept in `removed[]`, and `--accept-show` and the honest-exit record list it with its reason. |
| `node <pack>/bin/mission-state.js --init ... --kind qa --variant full\|fix\|regression [--estimate-first] [--mobile-minutes <n>]` | **0.12.0.** Starts a QA mission. It needs no plan, receipt or bug document, and freezes the QA scope as `full`. `--variant` is required and belongs to this kind only. `--estimate-first` makes the mission stop for your approval of its estimate. `--mobile-minutes` is the mission-wide device-minute budget. See [QA missions](/workflows/qa-and-design/#qa-missions). |
| `node <pack>/bin/mission-state.js --mint-id` and `--init ... --mission-id <id>` | **0.12.0.** `--mint-id` prints a fresh mission id and starts nothing. `--mission-id` makes a new mission use that id (8 to 128 letters, digits, `_` or `-`). `/fix-bugs ado=` uses the pair so its bug document and ADO tags can carry the id. |
| `node <pack>/bin/mission-state.js --estimate --cases <n> --device-minutes <n> --minutes-source "<text>" --credits <n> --credits-source "<text>" [--report <path>]` | **0.12.0.** An estimate-first QA mission records its estimate and parks in `human-blocked-confirmed`, waiting for you. Each number carries its source in words. |
| `node <pack>/bin/mission-state.js --approval [--apply] [--json]` | **0.12.0.** Reads the approval you gave in the app: `APPROVAL none`, `APPROVAL invalid: <why>` or `APPROVAL valid budget=<n> by=<who> at=<time>`. Exits 0 only for valid. With `--apply`, a valid approval becomes the mission's `mobile-minutes` and the state goes back to `active`. An invalid one changes nothing. |
| `node <pack>/bin/mission-state.js --clear --estimate-declined` | **0.12.0.** A person ends a QA mission that is waiting for its estimate: exit PARTIAL, test registry kept. What **End** does in the Missions drawer. An agent is refused. |
| `node <pack>/bin/mission-state.js --policy-set --name "<row>" --at <path:line>` and `--policy-show` | **0.12.0.** Records where a plan's Policy Values row lives in the code, in the acceptance ledger, so the plan is never edited. `--policy-show` is read only: each row, whether its location comes from the plan, the ledger or nowhere, and whether the value is there now. See [Missions](/workflows/missions/#tying-criteria-to-the-plan-rules-v2). |
| `kiroctl mission-report [--dir] [--transcript]` | Write a local, secret-scrubbed diagnostics bundle for auditing a mission run (no upload). **0.11.0.** It finds the grill receipt beside the plan (`<plan folder>/.kiro/grill-receipts/<hash>.json`). After a clear it reads the plan path, plan hash and receipt kind from the honest-exit record, and prints e.g. `grill-receipt=yes (imported)`. Before, a cleared mission always showed `grill-receipt=no`. |
| `kiroctl telemetry status \| repair \| flush \| config \| project \| probe-allowlist` | Adoption telemetry: identity + queue + connection health, run the self-repair now, manual flush, endpoint config, Mission Control project pin, and (maintainers) send two real events to check Mission Control accepts the `project_status` and `hours_source` fields. |
| `kiroctl sop status \| signout` | Mission Control sign-in (telemetry + SOP standards): show the connection state, or sign out. Sign **in** only in the app (`kiroctl gui` → "Sign in with Mission Control"). |
| `kiroctl sop bypass --hours <1-72> [--reason mc-outage\|no-browser\|other] \| --clear` | Time-limited, logged bypass of the sign-in gate (reported to Mission Control). |
| `kiroctl sop nudge` | What the installer runs at the end: signed out → open the app on its sign-in banner, or print the instruction (no display / `KIRO_NO_GUI=1`). |
| `kiroctl sop token [--force]` | Tooling: print a fresh id-token from the stored sign-in (`--force` re-mints). |

## What doesn't exist

- **No `link` / `unlink`.** Project binding happens at `kiroctl project new` /
  `kiroctl open` time; staying current is `kiroctl sync`.
- **No `install @latest`.** Updating the CLI itself is `kiroctl update`.
