## 0. One-shot bootstrap (new / near-bare machine)

If the machine doesn't yet have Node, Kiro CLI (or, on Windows, WSL), use the
**bootstrap** scripts — they install the prerequisites (via `fnm` for a pinned
Node LTS, the official `kiro-cli` installer) and then run the pack installer for
you. Everything is **idempotent** (re-running only fills what's missing) and
**detect-and-report** (a blocked prerequisite is reported with the fix, never a
half-install).

<Aside type="note" title="Download needs GitHub access (the repo is private)">
`revstar.ai` is a **private** repo, so there is no anonymous `curl | bash` — the
download is authenticated. You need a **GitHub account added to the RevStar org**
and **git** (ships with macOS Command Line Tools and inside WSL). Sign in once
with `gh auth login` or your SSH key, then clone and run the bootstrap below.
</Aside>

<Tabs syncKey="os">
  <TabItem label="macOS" icon="apple">
    ```sh
    # git comes from the Command Line Tools (xcode-select --install) if missing
    git clone https://github.com/revstarconsulting/revstar.ai.git
    cd revstar.ai
    ./scripts/bootstrap-macos.sh              # add --arm-safe to arm the inject-only gates
    ```
    No Homebrew required — `fnm` installs Node per-user.
  </TabItem>
  <TabItem label="Linux / WSL" icon="linux">
    ```sh
    sudo apt-get update && sudo apt-get install -y git   # if git is missing
    git clone https://github.com/revstarconsulting/revstar.ai.git
    cd revstar.ai
    ./scripts/bootstrap-wsl.sh                # add --enable-passwordless-sudo to opt in (below)
    ```
  </TabItem>
  <TabItem label="Windows" icon="seti:windows">
    A bare Windows box has no git yet, so grab just the Stage-1 script from the
    GitHub web UI (signed in): open
    [`scripts/bootstrap-windows.ps1`](https://github.com/revstarconsulting/revstar.ai/blob/v1/scripts/bootstrap-windows.ps1)
    and click **Download raw file**, then run it in an **elevated** PowerShell:
    ```powershell
    .\bootstrap-windows.ps1
    ```
    Stage 1 installs WSL (+ a distro). If Windows needs a reboot it tells you;
    otherwise launch the distro once (to create your Linux user). Then run the
    **Stage-2** command it prints inside WSL — a clone + `bootstrap-wsl.sh`:
    ```sh
    git clone https://github.com/revstarconsulting/revstar.ai.git ~/revstar.ai \
      && cd ~/revstar.ai && ./scripts/bootstrap-wsl.sh
    ```
  </TabItem>
</Tabs>

<Aside type="tip" title="Already signed in with gh? Grab a single script without a full clone">
With `gh` installed and authenticated you can pull just one bootstrap script:

```sh
gh api repos/revstarconsulting/revstar.ai/contents/scripts/bootstrap-macos.sh \
  -H "Accept: application/vnd.github.raw" > bootstrap-macos.sh && bash bootstrap-macos.sh
```
</Aside>

<Aside type="caution" title="Passwordless sudo — opt-in, security tradeoff">
A fully autonomous mission runs commands non-interactively, so a `sudo` that
prompts for a password will **hang** (there's no TTY to answer it). You can
grant passwordless sudo so missions don't stall:

```sh
./install.sh --enable-passwordless-sudo        # or: ./scripts/enable-passwordless-sudo.sh
```

This writes a `visudo`-validated `/etc/sudoers.d/90-revstar-kiro` after you
confirm. **`NOPASSWD` means this user can run `sudo` with no password** — fine on
a personal dev box, but it may violate policy on a shared/corp machine, so it is
**opt-in and never applied by the default install**. Scope it with
`--commands "apt-get,systemctl"` instead of all commands, and undo any time with
`sudo rm /etc/sudoers.d/90-revstar-kiro`. `kiroctl doctor` tells you whether sudo
will prompt (and so whether missions would hang).
</Aside>

Already have Node + Kiro CLI (+ WSL on Windows)? Skip to the manual steps below.

## 1. Prerequisites

- **Node.js 18+**
- **git** with access to the private repos (SSH key or `gh` login)
- **[Kiro CLI](https://kiro.dev)** (`kiro-cli`) installed and on your `PATH`
- **Windows only:** WSL2 with a Linux distro (the CLI runs inside WSL)

## 2. Get the two repos

RevStar.ai ships as two repos, cloned **side by side**:

```sh
git clone https://github.com/revstarconsulting/revstar.ai.git
git clone https://github.com/revstarconsulting/revstar.ai-registry.git
```

`revstar.ai` holds the `kiroctl` CLI and installers; `revstar.ai-registry` holds the
content pack (agents, skills, gates, steering).

<Aside type="caution" title="Use git clone — not a “Download ZIP”">
A GitHub ZIP download strips the executable bits off the installer scripts and
gives you no `kiroctl update` path — a zip-based install **silently skips the
desktop launcher**. Always `git clone`.
</Aside>

<Aside type="tip" title="Let your Kiro do it">
You can hand this to an existing Kiro session:

> `git clone` https://github.com/revstarconsulting/revstar.ai.git and
> https://github.com/revstarconsulting/revstar.ai-registry.git side by side, then from
> inside `revstar.ai` run the installer for my OS with
> `KIRO_REGISTRY_ROOT=../revstar.ai-registry`. Then verify with `kiroctl doctor` and
> `kiroctl doctor --governance`. Don't commit any secrets.
</Aside>

## 3. Run the installer

From inside `revstar.ai`, point the installer at your `revstar.ai-registry` clone:

<Tabs syncKey="os">
  <TabItem label="macOS" icon="apple">
    ```sh
    KIRO_REGISTRY_ROOT=../revstar.ai-registry ./installers/install-macos.sh
    ```
  </TabItem>
  <TabItem label="Linux" icon="linux">
    ```sh
    KIRO_REGISTRY_ROOT=../revstar.ai-registry ./installers/install-linux.sh
    ```
  </TabItem>
  <TabItem label="Windows" icon="seti:windows">
    Run in PowerShell (it provisions the WSL side and the Windows launcher):
    ```powershell
    $env:KIRO_REGISTRY_ROOT="..\revstar.ai-registry"
    .\installers\install-windows.ps1
    ```
  </TabItem>
</Tabs>

Add `--arm-safe` to also arm the inject-only gates (they can't block anything —
they only inject mission state and write turn receipts).

### What the bootstrap does

1. Copies `steering/` and `skills/` from the registry into `$KIRO_HOME`.
2. Writes the `dev`, `coder`, and `scout` agent configurations.
3. Sets `chat.defaultAgent` to `dev`.
4. Asserts the model pins (Opus for `dev`, Sonnet for `coder`/`scout` — never
   Haiku, never `auto`).
5. Runs the governance guard against the registry's rules.
6. Wires the Playwright and Azure DevOps MCP servers.
7. Links the `kiroctl` binary onto your `PATH` and installs the desktop launcher.
8. Records an install manifest so `kiroctl doctor`/`kiroctl update` know the layout.

## 4. Verify

```sh
kiroctl doctor
node ../revstar.ai-registry/kiro/gates/selftest.js
kiroctl doctor --governance
```

`kiroctl doctor` reports the install is healthy; the gate selftest prints
**60/60**; governance reports **OK**.

## 5. Use the desktop app

Everything day-to-day happens in the **RevStar.ai project GUI** — one identical local
web app on macOS, Windows and Linux. Launch it from the **“RevStar.ai - New Project”**
desktop icon the installer created — it now carries the **RevStar brand icon** on all
three platforms (a `.desktop` entry on Linux, an app bundle on macOS, a `.lnk` on
Windows) — or run:

```sh
kiroctl gui
```

It opens in your default browser on `127.0.0.1` (loopback only, gated by a
per-launch token). The app is a **two-pane, project-first** layout: your
projects on the left, the selected project's editable detail on the right.

### 5a. The project list and status badges

The left pane lists every project you've created, each with three status
badges so you can see what needs attention without opening it:

- **SSO** — signed in, or needs sign-in.
- **ADO** — ready, or not set up.
- **Repos** — present, or one or more missing.

A **filter** box at the top narrows the list as you type. Click a project to
load its detail on the right. Folders on disk that look like projects but
aren't registered yet appear below the list under **Other folders found**,
each with a one-click **Set up**.

### 5b. Edit a project in place

Selecting a project shows its full detail on the right, split into
inline-editable sections — no separate screens, no re-running a wizard to
change something:

<Steps>

1. **Client & sign-in** — the client's Identity Center start URL, region, and
   AWS account; **Sign in** or **Re-authenticate**; and, when the client is
   shared, which other projects use it.
2. **Azure DevOps** — the board mode (**RevStar ADO**, the **client's own
   ADO**, or **none**), the org URL, the ADO project, the project manager
   (a typeahead against your ADO project's members where a PAT allows it,
   otherwise free text), and the **PAT this project uses** — pick any saved PAT
   or **none**. Org, project and PM apply to the client (and any projects that
   share it); the PAT binds this project only. Manage saved PATs in **Settings**.
3. **Repos** — every repo in the project, added by **git URL** (cloned) or
   **local path** (linked, with a **Browse…** picker). **Remove** first shows a
   git-safety preview — a dirty working tree, unpushed commits, or no
   upstream — so you don't lose work by accident.
4. **QA environment** — staging URL, environment, target branch, and optional
   backend access, kept in sync with the project's `qa-contract.json`.

</Steps>

<Aside type="caution" title="Cloning uses your own git credentials">
Private-repo clones use your existing git/GitHub credentials (SSH or `gh`). A URL
with an embedded credential (`https://user:token@…`) is **rejected** — use SSH or
a credential helper.
</Aside>

### 5c. Create a project — the guided wizard

The **New project** button (top-right) opens a single guided wizard:

**Client → Project & repos → Azure DevOps (RevStar / client's own / none) → QA
→ Review → Create → Sign in → Launch**

Nothing is saved until you confirm on the **Review** step — Create then writes
everything at once. If a repo fails to clone, you get a **Retry** rather than a
half-created project.

### 5d. Settings and Azure DevOps PATs

The gear icon opens the **Settings** drawer:

- **Default ADO** — the org/PAT new projects default to when they pick RevStar ADO.
- **Saved PATs** — add, rename, replace the secret on, or delete a PAT. A PAT
  is saved once and reused across every project that needs it; it's stored in
  your OS keychain (with a `0600`-file fallback) and never shown back or
  written to config.
- **Unused clients** — clients no projects currently use, with a one-click delete.

<Aside type="tip">
Prefer the CLI? `kiroctl client set-pat --slug <client>` reads the PAT from stdin
(never the argument list).
</Aside>

Each project also has a **Report a bad run** action, for flagging a session
that went wrong.

## 6. Updating later

```sh
kiroctl update
```

A verified pull of both repos + reinstall — bolt-on, never subtract, so your own
customizations are preserved. Restart your Kiro session afterward so steering,
skills and MCP servers reload. (On Windows, run it inside WSL.)

## Release channels — stable vs beta

RevStar.ai ships on two channels:

- **`stable`** — the **default for a new install**. A vetted line, promoted from
  beta only after a full QA pass. This is what you get unless you ask otherwise.
- **`beta`** — the active line where new features land first. Opt in at install
  time:

  ```sh
  ./install.sh --channel beta          # macOS / Linux / WSL
  .\install.ps1 -Channel beta          # Windows PowerShell
  ```

  (and `--channel stable` / `-Channel stable` is always available to be explicit).

The channel is recorded in `kiroctl-install.json`, and `kiroctl update` then pulls
that channel's line — so a stable install stays on stable and a beta install stays
on beta, with no flags to remember. **Re-installing keeps the channel you already
have** unless you pass `--channel`, so updating in place never moves you between
channels. `kiroctl version` and `kiroctl doctor` show your current channel and
version, and the GUI header shows them too.

<Aside type="note">
Existing installs made before channels existed continue to track **beta** (the
original line) — there is no silent migration. New features land on **beta**
first; anything not yet promoted to stable is marked *beta* on the page. Switch
channels by re-installing with `--channel beta` or `--channel stable`.
</Aside>
